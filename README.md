# BadgeBridge

**BadgeBridge** («Точки уведомлений») — маленькое Android-приложение, которое делает
на рабочем столе **значки приложений с числом уведомлений**, как в стоковых
лаунчерах. Работает через обычный виджет 1×1, без root и без сторонних лаунчеров.

![](screenshots/widget.png)

## Что оно делает

- Вы выбираете несколько приложений (Telegram, 4PDA, RuStore…).
- Для каждого на рабочем столе появляется значок этого приложения.
- На значке рисуется **красный бейдж с цифрой** — сколько уведомлений этого
  приложения сейчас лежит в «Центре уведомлений».
- Под значком написано `Название · N`.
- Нажатие на значок открывает приложение.

Если уведомлений нет — бейдж исчезает.

## Стиль бейджа

Бейдж намеренно сделан **так же, как системные бейджи OriginOS** (замерен по
скриншоту системного значка «Сообщения» на 1440×3168):

![](screenshots/compare.png)

| Параметр | OriginOS | BadgeBridge |
|---|---|---|
| Диаметр круга | 72 px | Ø50 в холсте → 63 px на экране (28% иконки) |
| Положение круга | на верхнем-правом углу иконки, выступает наружу | тот же угол: `BADGE_X = SIZE - BADGE_R`, `BADGE_Y = BADGE_R` |
| Размер иконки | 206 px в слоте дока | 222 px (87% ячейки), **центрирована** в виджете |
| Цвет | `#F54A2A` | `rgb(245, 74, 42)` |
| Обводка / тень | нет | нет |
| Высота цифры | ~43% диаметра | 30 px шрифта на Ø50 |
| Скругление угла иконки | ~29% стороны | 50 px на 174 px |

Ячейка виджета фиксирована, поэтому композиция «иконка + бейдж» должна ровно
вписываться в неё: `SIZE = ICON + MARGIN`, где `MARGIN` — насколько круг
выступает за угол иконки. Иконка лежит в холсте с одинаковым отступом со всех
сторон (`MARGIN = 13`), поэтому её центр совпадает с центром ячейки и с
подписью под ней — значок не «съезжает» влево.

Числа больше 99 показываются как `99+`.

## Почему именно так

Android не даёт обычному приложению менять иконки лаунчера. Единственный легальный
способ — **App Widget**. BadgeBridge использует его: значок рисуется кодом
(`Store.icon()`), а число берётся из `NotificationListenerService`.

Ограничения платформы:

- нужен доступ «к уведомлениям» (даётся через системный диалог Android);
- виджет обновляется, когда приходят/уходят уведомления, а не по таймеру;
- постоянные («фоновые») уведомления с флагами `FLAG_SKIP` и `FLAG_AUTOMATIC`
  не считаются — иначе счётчик был бы всегда «1».

## Требования

- Android 8.0+ (API 26).
- Разрешения: доступ к уведомлениям (даётся через системный диалог), `INTERNET`
  и `REQUEST_INSTALL_PACKAGES` — нужны только для автообновления.
- На устройствах vivo/OriginOS закрепление значка идёт через фирменный
  `JumpOriginWidgetActivity` (`com.bbk.launcher2`), на остальных — через
  стандартный `requestPinAppWidget`. Если лаунчер не поддерживает закрепление,
  показывается инструкция.

## Установка

Скачайте APK из [releases](https://github.com/demoonk/BadgeBridge/releases) и
установите как обычный APK.

Дальше:

1. Откройте приложение → **«Разрешить доступ»** → в системном диалоге
   **«Разрешить»** (на vivo: Настройки → Уведомления устр. и прил. →
   «Точки уведомлений» → «Добавить» → «Доступ к уведомлениям»).
2. Добавьте нужные приложения кнопкой **«+ Добавить приложение»**.
3. Нажмите **«Добавить значок на экран»** — значок появится на рабочем столе.
4. Меняется приложение долгим нажатием на значок → **Настроить**.

## Автообновление

![](screenshots/autoupdate.png)

С версии 0.4.6 приложение само следит за релизами:

1. При открытии экрана запрашивается
   `https://api.github.com/repos/demoonk/BadgeBridge/releases/latest`.
2. Версия из `tag_name` сравнивается с `versionName` установленного APK.
3. Если вышла новая версия — в карточке «Обновления» появляется кнопка
   **«Обновиться до X.Y.Z»**.
4. Нажатие скачивает APK прямо с GitHub в кэш приложения и открывает
   системный установщик через `ACTION_INSTALL_PACKAGE` и собственный
   `ApkProvider` (`content://local.badgebridge.fileprovider/…`).

Android (и OriginOS на vivo) в любом случае показывает подтверждение
установки — тихая установка без подтверждения возможна только с root. Поэтому
обновление выглядит как «скачал сам → один клик в диалоге vivo».

Кнопка **«Проверить снова»** делает повторную проверку вручную.

## Сборка

Проект собирается без Gradle — только инструменты Android SDK. Это сделано
специально: APK получается меньше 30 КБ и собирается одной командой.

```powershell
$env:ANDROID_HOME = "C:\path\to\android-sdk"
.\build.ps1
```

Получите `dist\BadgeBridge-0.4.6.apk`. Если `badge.keystore` нет, `build.ps1`
создаст его автоматически (`keytool`).

Что происходит при сборке:

```
aapt2 compile  →  aapt2 link (manifest + res)  →  javac  →  d8  →  pack.py  →  zipalign  →  apksigner
```

`pack.py` обязателен: с Android 11 `resources.arsc` должен быть **не сжат**
и выровнен на 4 байта, иначе установка падает с
`Targeting R+ requires the resources.arsc of installed APKs to be stored
uncompressed and aligned on a 4-byte boundary`.

## Структура

```
src/local/badgebridge/
  Store.java          # счётчики, отрисовка значка, закрепление виджета
  Listener.java       # NotificationListenerService, подсчёт уведомлений
  Widgets.java        # AppWidgetProvider
  MainActivity.java   # интерфейс (собирается программно, без XML-разметки)
  ConfigureActivity.java  # «Настроить» для уже закреплённого значка
  OpenActivity.java   # открывает приложение по нажатию на значок
  PinResult.java      # ответ лаунчера о закреплении
  Boot.java           # переподключение слушателя после перезагрузки
res/                  # layout/widget.xml, xml/widget.xml, drawable/app_icon.xml
AndroidManifest.xml
build.ps1
pack.py
```

## Как считается число

`Listener.scan()` берёт `getActiveNotifications()` и для каждого уведомления
из выбранного списка проверяет флаги:

| Флаг | Учитывается? |
|---|---|
| обычный | да |
| `FLAG_SKIP` (512) | нет |
| `FLAG_AUTOMATIC` (2) | нет |
| уведомление другого пользователя | нет |

Тексты уведомлений не сохраняются и никуда не отправляются — используется
только пакет приложения и флаги. Сеть приложению не нужна вообще.
